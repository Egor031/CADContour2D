## 1. Назначение программы

Программа предназначена для обработки плоских облаков точек, полученных при сканировании плоских деталей.

Основная цель — восстановить по облаку точек геометрию детали:

- внешний контур;
- отверстия;
- внутренние вырезы;

а затем получить компактный редактируемый двумерный CAD-контур и экспортировать его в DXF для дальнейшей работы, в том числе в Siemens NX.

Программа должна быть рассчитана на большие исходные файлы размером в несколько гигабайт и на облака, содержащие миллионы и более точек.

---

## 2. Целевая среда

Программа должна работать на:

- Windows 10 x64;
- Windows 11 x64.

Целевой компьютер может быть слабым офисным ПК.

Не предполагаются:

- мощный процессор;
- большой объём оперативной памяти;
- дискретная GPU;
- SSD.

Исходные файлы могут находиться:

- на HDD;
- на медленном сетевом ресурсе.

Программа не должна требовать загрузки исходного облака целиком в оперативную память.

Трудоёмкие операции должны проектироваться с учётом медленного дискового и сетевого ввода-вывода.

### 2.1. Пользовательский интерфейс

Первая версия должна иметь удобный desktop GUI с качественным современным внешним видом, удобным редактированием геометрии, понятным отображением состояний, качественной типографикой и масштабируемыми иконками.

Основной пользовательский интерфейс первой версии должен быть на русском языке. Это относится как минимум к меню, кнопкам и действиям, названиям пользовательских параметров, диалогам, предупреждениям, состояниям и сообщениям об ошибках для пользователя.

Это не требует перевода имён C++ классов, QML identifiers, API, исходного кода, внутренних enum, технической документации и общепринятых технических идентификаторов. Английские технические названия операций в документации не предписывают английские надписи в UI.

Небольшой UI overhead допустим ради заметного улучшения UX при сохранении отзывчивости. Не требуются декоративная перегрузка, чрезмерные анимации и неоправданно тяжёлые визуальные ресурсы.

## 3. Единицы измерения

Основные геометрические единицы проекта — миллиметры.

Во внутренней геометрической модели:

```text
1.0 = 1 мм
```

В миллиметрах задаются:

- координаты;
- размеры отверстий;
- `cell`;
- геометрические допуски;
- максимальное расстояние выборки точек от rough-геометрии;
- другие физические параметры обработки.

Экранные пиксели и пиксели density map не являются геометрическими единицами.

---

## 4. Входные данные

Программа должна поддерживать файлы:

```text
.asc
.xyz
```

Оба расширения рассматриваются как один логический формат.

Исходное облако получается линейным сканированием. Соседние линии могут накладываться, поэтому небольшие участки отдельных линий иногда выступают относительно основной границы. Такие измеренные точки сами по себе не являются шумом и рассматриваются как потенциальная граница детали. В других местах граница может быть практически ровной линией точек.

Структура файла:

```text
X Y Z
X Y Z
X Y Z
...
```

Требования к формату:

- заголовок отсутствует;
- каждая строка содержит одну точку;
- координаты представлены вещественными числами;
- десятичный разделитель — точка;
- количество знаков после десятичной точки не фиксировано;
- координата `Z` для корректного плоского сканирования должна быть равна нулю.

Примеры допустимого представления нулевого `Z`:

```text
0
0.0
0.00
0.00000
```

---

## 5. Ненулевая координата Z

Если при импорте обнаружена хотя бы одна точка с `Z != 0`, программа должна предупредить пользователя, что файл не соответствует ожидаемому плоскому облаку.

Пользователь должен иметь возможность:

- продолжить импорт;
- отменить импорт.

Программа не обязана выполнять дополнительный анализ ненулевых значений `Z`.

Ненулевой `Z` рассматривается как нетипичная или ошибочная ситуация исходных данных.

---

## 6. Импорт и постоянный кэш

Исходный `.asc` или `.xyz` не должен многократно перечитываться при обычной работе с проектом.

При первоначальном импорте программа должна создать локальный постоянный кэш точек.

Кэш должен:

- сохраняться между запусками программы;
- содержать данные, достаточные для последующей работы с реальными точками;
- использоваться вместо повторного текстового разбора исходного файла;
- позволять продолжать работу с проектом после закрытия программы.

После успешного импорта обычная работа с проектом не должна зависеть от доступности исходного `.asc` или `.xyz`.

Исходный файл может:

- находиться на отключённом сетевом ресурсе;
- быть перемещён;
- стать временно недоступным.

Это не должно препятствовать продолжению работы, если необходимый кэш уже создан.

## 7. Построение карты плотности

Карта плотности создаётся как отдельная операция по явной команде пользователя.

Перед построением пользователь задаёт размер ячейки:

```text
cell
```

`cell` задаётся в миллиметрах.

Одна ячейка density map соответствует физической области:

```text
cell × cell
```

и одному пикселю результирующей карты.

Для каждой ячейки определяется количество исходных точек, попавших в соответствующую область.

С ростом количества точек визуальная интенсивность пикселя не должна уменьшаться. Конкретное encoding, включая квантование и возможное saturation, остаётся алгоритмическим решением.

Перед построением проверяются `cell > 0`, конечность параметров, представимость размеров карты, arithmetic overflow и возможность использования требуемых ресурсов. При невозможности построения выполняется безопасный отказ без публикации частичной карты и без разрушения предыдущего корректного результата.

---

## 8. Фиксированный размер cell

`cell` является свойством конкретной построенной density map.

После построения карты:

```text
1 пиксель карты = cell × cell мм
```

Это соотношение не изменяется.

Масштабирование изображения в интерфейсе:

- не изменяет `cell`;
- не повышает физическое разрешение карты;
- не создаёт новые данные;
- влияет только на отображение.

Чтобы использовать другое значение `cell`, пользователь должен явно перестроить density map.

Перестроение карты с другим `cell` создаёт новую растровую основу первого этапа.

---

## 9. Данные первого этапа

После построения density map автоматические операции первого этапа должны работать с построенной PNG-картой.

На первом этапе исходные точки не используются для точного восстановления геометрии.

Первый этап предназначен для:

- выбора нужной детали;
- приблизительного поиска внешнего контура;
- приблизительного поиска отверстий;
- поиска внутренних вырезов;
- ручной корректировки найденных объектов;
- подготовки областей для последующей работы с реальными точками.

Точное восстановление геометрии выполняется только на втором этапе.

---

## 10. Выбор детали и ROI

Один исходный скан может содержать несколько деталей.

Пользователь ограничивает рабочую область прямоугольной областью или лассо. ROI / Crop Selection является неразрушающей относительно исходной density map: последующие rough-операции используют выбранную область, а исходная карта остаётся доступной.

Пользователь может отменить обрезку, вернуть полную исходную карту и изменить выбранную область.

Если ROI содержит несколько независимых кандидатов и операция не может однозначно определить нужную деталь, программа сообщает об этом пользователю. Автоматический выбор самой большой детали не выполняется.

Изменение ROI после начала precise-stage подчиняется правилу полного сброса второго этапа (§21).

---

## 11. Черновой внешний контур

По явной команде пользователя программа должна находить ориентировочный внешний контур детали по density map.

На первом этапе внешний контур может быть представлен замкнутой полилинией.

На rough-этапе не требуется восстанавливать точные CAD-примитивы:

- прямые;
- дуги;
- сплайны.

Пользователь должен иметь возможность:

- перемещать вершины rough-полилинии;
- добавлять вершины;
- удалять вершины;
- вручную корректировать форму контура.

Черновой контур используется как приблизительное описание геометрии и как основа для отбора реальных точек на втором этапе.

---

## 12. Повторное построение внешнего rough-контура

Повторный поиск полностью заменяет внешний rough-контур по текущей density map и ROI. Общие правила предупреждения, отсутствия автоматического слияния и Undo определены в §18.

---

## 13. Поиск отверстий на первом этапе

Поиск отверстий выполняется только по явной команде пользователя.

Программа должна искать приблизительно круглые внутренние пустые области, соответствующие отверстиям.

Пользователь должен иметь возможность задавать диапазон размеров:

```text
Искать отверстия диаметром больше: ...
Искать отверстия диаметром меньше: ...
```

Размеры задаются в миллиметрах.

Практический сценарий проекта должен позволять исключать отверстия диаметром 4 мм и меньше, например отверстия под гвозди.

Отверстия вне выбранного диапазона считаются исключёнными областями: они не должны автоматически появляться как внутренние вырезы, использоваться для выборки Reduced Point Cloud или появляться на precise-stage. Пользователь может явно создать или переклассифицировать такую область как вырез.

Верхняя граница диапазона может быть неограниченной. Заданные значения должны быть допустимыми конечными величинами, а ограниченный диапазон — логически корректным.

---

## 14. Редактирование rough-отверстий

Пользователь должен иметь возможность:

- добавить отверстие, которое не было найдено автоматически;
- удалить ошибочно найденное отверстие;
- изменить центр отверстия;
- изменить его радиус или диаметр.

Автоматически найденные отверстия не считаются окончательным результатом до проверки пользователем.

Если пользователь удалил отверстие и не переклассифицировал его как вырез, эта область считается ненужной. Обычные последующие операции не должны возвращать её как cutout, включать её область в выборку Reduced Point Cloud или создавать precise-hole. Явное создание/переклассификация области пользователем разрешено; исключение для полного повторного поиска отверстий определено в §16.

---

## 15. Группировка отверстий

Программа должна поддерживать автоматическое объединение отверстий близкого размера в HoleGroup. Пользователь может исправить группировку и задавать/корректировать rough-размеры отверстий.

Групповой размер rough-stage (`rough group size`) используется для организации похожих отверстий, удобного редактирования, приблизительного описания и определения областей выборки реальных точек.

HoleGroup существует на обоих этапах. При переходе на precise-stage принадлежность отверстий к группам сохраняется. Центр и precise measured size каждого отверстия уточняются индивидуально по реальным точкам (§29).

Rough group size не является жёстким требованием одинакового диаметра precise-отверстий. В DXF экспортируются индивидуальные precise-размеры.

Группировка должна использовать физически осмысленный критерий, а не универсальный жёстко заданный `epsilon`.

---

## 16. Повторный поиск отверстий

Явный повторный запуск «Найти отверстия» выполняет полное новое автоматическое построение по текущим raster inputs и диапазону размеров. Предыдущий набор заменяется.

Ручные перемещения, удаления, добавления и изменения размеров старого набора не сохраняются. Ранее удалённое отверстие может быть найдено заново; отверстия вне текущего диапазона по-прежнему исключаются.

Новый набор не сопоставляется автоматически со старым. Общие правила предупреждения и Undo определены в §18.

---

## 17. Внутренние вырезы

Внутренние пустые области детали, которые:

- не являются отверстиями или исключёнными областями по §§13–14;
- имеют достаточный размер;
- находятся внутри внешнего контура,

должны рассматриваться как кандидаты на внутренние вырезы.

Пользователь должен иметь возможность:

- изменить контур выреза;
- удалить ошибочно найденный вырез;
- вручную скорректировать его форму;
- явно создать или переклассифицировать исключённую область как вырез.

Очень маленькие пустые области не должны автоматически превращаться в геометрические вырезы.

Одиночные или очень малые пустые области могут рассматриваться как шум.

Критерий минимального значимого размера должен учитывать физический масштаб `cell`, а не быть произвольным постоянным количеством пикселей.

---

## 18. Взаимодействие операций первого этапа

Необходимо различать повторный запуск той же операции и запуск последующей операции.

### Повторный запуск той же операции

Он полностью заменяет соответствующий результат без автоматического слияния с ручными изменениями. При наличии ручных изменений перед заменой требуется предупреждение. Замена является одним логическим Undo-действием внутри rough-stage.

Для отверстий действует специальное правило §16: полный повторный поиск может заново найти ранее удалённые отверстия.

Например:

```text
Найти отверстия
→ ручное редактирование
→ Найти отверстия повторно
```

означает новый поиск с заменой текущего набора отверстий.

### Запуск другой операции

Она использует текущее состояние rough-геометрии, включая ручные изменения и исключённые области. Запуск другой операции не отменяет исключение отверстий (§§13–14).

Например:

```text
Найти внешний контур
→ пользователь исправил контур
→ Найти отверстия
```

Поиск отверстий должен выполняться относительно текущего исправленного внешнего контура.

---

## 19. Явный запуск трудоёмких операций

Потенциально трудоёмкие операции выполняются только после явной команды пользователя.

К таким операциям относятся как минимум:

- импорт;
- построение density map;
- поиск внешнего контура;
- поиск отверстий;
- поиск внутренних вырезов;
- создание облегчённого облака;
- уточнение внешнего контура;
- уточнение отверстий;
- уточнение внутренних вырезов;
- оптимизация итоговой геометрии.

Изменение пользователем:

- вершины;
- отверстия;
- выреза;
- параметра;
- точки;
- любого другого объекта

не должно автоматически запускать тяжёлый пересчёт.

---

## 20. Актуальность результатов и неприменённые изменения

Внутри одного этапа изменение входных данных или параметров может сделать построенный зависимый результат неактуальным. Программа сообщает об этом, но не запускает тяжёлый пересчёт автоматически.

В precise-stage существующая geometry после изменения влияющих на неё точек или параметров соответствует предыдущему состоянию данных, пока пользователь явно не запустит refine/rebuild. В UI это описывается как «неприменённые изменения».

Экспорт такой текущей построенной geometry допускается только после предупреждения и явного решения пользователя (§34).

Для изменения rough-данных после начала precise-stage действует специальный полный сброс (§21), а не сохранение старого второго этапа как Outdated.

---

## 21. Переходы между этапами

### Rough Stage → Precise Stage

Явный запуск Build Reduced Point Cloud считается подтверждением текущего rough-state для перехода. Отдельное состояние Confirmed Rough Geometry не требуется; подтверждение rough-state не означает Fixed precise geometry.

Из persistent point cache выбираются реальные точки около текущего внешнего rough-контура, rough-вырезов и активных rough-отверстий. Исключённые области (§§13–14) не участвуют в выборке.

Параметр выборки задаёт максимальное расстояние от rough-геометрии до исходной точки в миллиметрах. Для окружности расстояние определяется до самой окружности, а не до центра.

Цель — оставить только данные, необходимые для точного восстановления геометрии. Перед созданием dataset проверяются допустимость параметров, представимость размеров, overflow и возможность использования ресурсов. Failure не публикует частичный результат и не разрушает предыдущий корректный результат.

### Изменение Rough Stage после начала Precise Stage

Перед изменением данных первого этапа, включая ROI, программа предупреждает:

> Изменение данных первого этапа полностью сбросит второй этап и все выполненные в нём изменения. Этот сброс нельзя отменить через Undo.

Если пользователь отменяет действие, состояние не меняется. После подтверждения полностью сбрасываются:

- Reduced Point Cloud и ручные удаления точек;
- precise geometry и ручные изменения;
- Fixed states;
- результаты fitting и geometry optimization;
- другие данные второго этапа, зависящие от прежнего rough-state.

Сброс не поддерживает Undo. Хранить второй экземпляр данных второго этапа ради отмены не требуется. Обычный Undo/Redo внутри каждого этапа сохраняется (§31).

После сброса пользователь изменяет rough-stage и при необходимости снова явно запускает Build Reduced Point Cloud. Zoom/pan и другие изменения только отображения не сбрасывают этап.

---

## 22. Назначение второго этапа

Второй этап работает с реальными измеренными точками, а не с density PNG.

Его задача — построить финальную геометрию с заданной пользователем точностью.

Rough-геометрия используется как:

- начальное приближение;
- способ определить нужные области реальных точек;
- начальная классификация отверстий и вырезов.

Она не считается окончательной точной геометрией.

---

## 23. Редактирование точек

На втором этапе пользователь должен иметь возможность удалять точки, которые считает:

- ошибочными;
- шумовыми;
- посторонними;
- не относящимися к нужной геометрии.

Удаление точек из рабочего облегчённого облака (Reduced Point Cloud) не изменяет исходный persistent point cache.

Ручные удаления сохраняются вместе с проектом и после повторного открытия не должны неожиданно возвращаться. Явное полное перестроение Reduced Point Cloud создаёт новый рабочий набор; старые удаления не обязаны переноситься. Межэтапный сброс (§21) также удаляет эти изменения.

Если прилегающий к границе мусор нельзя надёжно отличить от реальных измеренных точек автоматически, его удаление остаётся задачей пользователя precise-stage.

---

## 24. Точная геометрия

По облегчённому облаку программа должна восстанавливать итоговую CAD-геометрию.

Минимальный требуемый набор геометрических объектов:

- прямые (domain `LineSegment`, DXF `LINE`);
- дуги окружностей (`CircularArc`, `ARC`);
- окружности (`Circle`, `CIRCLE`);
- сплайны (`BSpline`, `SPLINE`).

Дополнительные типы кривых могут быть добавлены позднее, если реальные данные покажут их необходимость.

Финальный контур не должен без необходимости представляться огромной полилинией из большого количества коротких сегментов.

---

## 25. Минимизация количества объектов

В пределах заданного пользователем качества программа должна стремиться использовать минимальное или близкое к минимальному разумное количество CAD-объектов.

Если несколько типов представления удовлетворяют требованиям точности, предпочтение должно отдаваться более простому геометрическому представлению.

Например:

- прямая предпочтительнее сплайна, если участок является прямым в пределах допуска;
- дуга предпочтительнее сплайна, если участок является круговым;
- соседние совместимые элементы желательно объединять.

Требование не означает необходимость решать глобальную математическую задачу абсолютного минимума любой ценой.

Пользовательский tolerance позволяет заменить дискретную measured boundary компактным набором primitives вместо полилинии через каждую точку, сохраняя материал (§26). Цель — компактная и удобная для CAD-редактирования геометрия.

Refinement выбирает подходящие primitives и избегает заведомой избыточности. Дополнительная Geometry Optimization является отдельной явно запускаемой операцией, а не автоматическим последним проходом refinement.

---

## 26. Точность и направление допустимого отклонения

Пользователь должен иметь возможность задавать требуемый допуск построения финальной геометрии.

Допуск задаётся в миллиметрах.

Для автоматического построения контура на втором этапе допуск является **односторонним относительно материала детали**.

Автоматически построенный внешний контур не должен заходить внутрь материала. Пользовательский допуск не разрешает отклонение на запрещённую сторону.

Допустимое отклонение от измеренной границы разрешается только в сторону, при которой сохраняется дополнительный материал.

Практический принцип:

> Лучше автоматически оставить небольшой припуск и затем при необходимости удалить его вручную, чем автоматически удалить лишний материал и сделать заготовку непригодной.

Для внешнего контура это означает, что допустимое отклонение должно происходить наружу от детали.

Для внутренних отверстий и вырезов направление определяется тем же правилом сохранения материала: автоматическая геометрия не должна увеличивать удаляемую область за счёт материала детали.

Таким образом:

- внешний контур может быть немного увеличен в пределах допуска, но не уменьшен внутрь материала;
- отверстие или внутренний вырез может быть немного уменьшен в пределах допуска, но не увеличен в область материала.

Это правило относится к автоматически восстанавливаемой геометрии второго этапа.

Физические размеры и допуски должны быть положительными конечными значениями. Конкретные методы boundary/support extraction, robust filtering, интерполяции, fitting и технической проверки one-sided constraint остаются экспериментальными Open decision в algorithms.md.

Если алгоритм не может построить геометрию, одновременно удовлетворяющую заданному допуску и требованию не заходить в область материала, он не должен принимать нарушающий это правило результат как корректный.

В такой ситуации программа должна сообщить пользователю, что автоматическое построение с заданными условиями невозможно или требует ручной корректировки.

---

## 27. Непрерывность контуров

### Поддерживаемая топология первой версии

Одна деталь содержит один внешний контур, `0..N` отверстий и `0..N` внутренних вырезов. Внутренние области находятся внутри внешнего контура.

Не допускаются самопересечения внешнего и внутренних контуров, пересечения внешнего контура с внутренними, взаимные пересечения отверстий, вырезов и отверстий с вырезами, а также касания независимых контуров или границ.

Касающиеся области не интерпретируются как две независимые границы. Если геометрия допускает единый корректный контур, они должны описываться единой формой внешнего контура или внутреннего выреза. Некорректная топология не принимается как успешный финальный результат.

Вложенные острова материала внутри вырезов не поддерживаются. Отдельная несоединённая область материала рассматривается как другая деталь.

Методы intersection/touch validation и численные допуски проверки определяются реализацией и алгоритмами.

### Непрерывность одного контура

Финальные контуры должны быть топологически непрерывными. Запрет касаний независимых границ не относится к общим endpoints соседних CAD-примитивов одного контура, необходимым для C0 continuity.

Для соседних элементов обязательно совпадение общей конечной точки.

Любые типы соседних элементов могут образовывать угол, например:

```text
LineSegment ↔ LineSegment
LineSegment ↔ CircularArc
LineSegment ↔ BSpline
CircularArc ↔ CircularArc
CircularArc ↔ BSpline
BSpline ↔ BSpline
```

Соединение должно различать как минимум два смысловых режима:

```text
Corner
Tangent
```

Для `Corner` допускается изменение направления касательной.

Для `Tangent` должно обеспечиваться совпадение направления касательных.

Программа не должна автоматически сглаживать реальные углы детали.

Требования непрерывности не отменяют правило одностороннего допуска: обеспечение соединения соседних элементов не должно приводить к заходу автоматически построенного контура внутрь области материала.

---

## 28. Пользовательская геометрия на втором этапе

На втором этапе геометрический элемент, созданный или явно исправленный пользователем и зафиксированный им, должен рассматриваться как ограничение для последующих автоматических операций.

Автоматический алгоритм не должен произвольно изменять зафиксированный объект.

Он должен строить и уточнять оставшуюся свободную геометрию относительно зафиксированных пользовательских элементов.

Например, если пользователь установил прямую, соседние автоматически строящиеся элементы должны учитывать:

- её положение;
- её конечные точки;
- требуемый тип соединения.

Требование одностороннего автоматического допуска применяется к автоматически строящимся свободным элементам и не должно приводить к самовольному изменению зафиксированной пользователем геометрии.

Пользователь может снять Fixed и снова разрешить автоматическое изменение: `Automatic → Fixed → Automatic`. Снятие Fixed само по себе не запускает fitting.

---

## 29. Уточнение отверстий на втором этапе

На втором этапе программа не должна заново выполнять глобальный поиск всех отверстий.

Текущие активные rough-отверстия, принятые явным запуском Build Reduced Point Cloud, используются как известные объекты. Исключённые области не восстанавливаются автоматически.

По реальным точкам уточняются:

- положение центра;
- радиус или диаметр.

Принадлежность к HoleGroup сохраняется. Rough group size не ограничивает индивидуальный precise measured size; итоговый центр и размер каждого отверстия определяются по соответствующим реальным точкам.

One-sided constraint проверяется для всей итоговой окружности с её фактическими центром и радиусом. Уменьшение радиуса само по себе недостаточно, если одновременно изменён центр: удаляемая область не должна увеличиваться за счёт материала.

Отсутствие глобального поиска и соблюдение текущих объектов/исключений предотвращают повторное автоматическое создание ранее удалённых или замещённых отверстий. Fixed-поправки не изменяются при refinement (§28).

---

## 30. Уточнение внутренних вырезов

Внутренние вырезы, определённые на первом этапе, должны уточняться по соответствующим реальным точкам.

Их финальный контур должен строиться из подходящих CAD-примитивов.

Автоматически построенный контур внутреннего выреза должен соблюдать правило сохранения материала и не увеличивать удаляемую область за счёт области точек детали.

Пользователь должен иметь возможность:

- исправлять итоговую геометрию;
- удалять ошибочные элементы;
- добавлять необходимые элементы;
- фиксировать ручные исправления для последующих автоматических операций.

---

## 31. Undo/Redo

Ручные операции редактирования должны поддерживать Undo/Redo.

К ним относятся как минимум:

- перемещение геометрии;
- добавление элементов;
- удаление элементов;
- изменение контуров;
- изменение отверстий;
- изменение размеров;
- удаление точек;
- замена существующего результата повторной автоматической операцией.

Замена существующего результата повторной автоматической операцией является одним логическим Undo-действием внутри этапа.

Полный межэтапный сброс (§21) не поддерживает Undo. История отмены не должна через этот сброс возвращать данные второго этапа или обходить правило сброса при изменении rough-входов.

Сохранение полной истории Undo/Redo между запусками программы не является обязательным требованием.

## 32. Сохранение проекта

Пользователь должен иметь возможность закрыть программу и позднее продолжить работу с сохранённого состояния.

Рабочий проект должен сохранять как минимум данные, необходимые для восстановления:

- связи с импортированными данными;
- постоянного кэша;
- параметров density map;
- `cell`;
- выбранной области детали;
- rough-внешнего контура;
- rough-отверстий;
- принадлежности отверстий к HoleGroup и rough group sizes;
- rough-внутренних вырезов;
- Reduced Point Cloud или информации для его восстановления с сохранением ручных удалений точек;
- исключённых rough-областей;
- precise geometry;
- пользовательских изменений;
- пользовательских параметров обработки;
- информации об актуальности зависимых результатов.

Рабочее расширение формата проекта:

```text
.pc2dproj
```

Опубликованное сохранение ссылается только на полностью записанные согласованные project-owned datasets. Неудачное сохранение не уничтожает последнее корректное сохранённое состояние.

Точная внутренняя структура формата определяется отдельно.

## 33. Autosave и восстановление

Программа должна предусматривать защиту длительной ручной работы от потери при:

- аварийном завершении программы;
- сбое системы;
- других неожиданных прерываниях работы.

Должен существовать механизм автоматического сохранения или восстановления рабочего состояния.

Автоматическое сохранение не должно без необходимости уничтожать последнее корректное состояние, явно сохранённое пользователем.

Autosave/recovery следует тому же принципу согласованной публикации данных и сохранения предыдущего корректного состояния (§32). Конкретная стратегия определяется архитектурой.

## 34. Экспорт DXF

Финальная геометрия должна экспортироваться в DXF, пригодный для дальнейшей работы в CAD, в том числе Siemens NX.

Геометрические объекты должны по возможности сохранять собственный тип:

```text
LineSegment → LINE
CircularArc → ARC
Circle      → CIRCLE
BSpline     → SPLINE
```

Аналитическая геометрия не должна без необходимости превращаться в большое количество линейных сегментов.

Координаты и размеры экспортируются в миллиметрах.

Перед экспортом при наличии неприменённых изменений precise-входов программа предупреждает, что текущая построенная geometry ещё не перестроена с их учётом. Пользователь может отменить экспорт или явно продолжить экспорт текущей geometry. Exporter не применяет эти изменения и не запускает fitting самостоятельно.

Это разрешение не отменяет требования к финальной topology; оно относится к неприменённым входам, а не к принятию нарушающего обязательные контракты автоматического результата.

Конкретная версия DXF и окончательная совместимость с Siemens NX остаются Open decision до реальной проверки.

## 35. Основной пользовательский workflow

Основной сценарий работы:

```text
1. Открыть ASC/XYZ.

2. Импортировать файл и создать постоянный point cache.

3. Задать размер cell.

4. По явной команде построить density map.

5. Выбрать нужную деталь или рабочую область.

6. По явной команде найти rough-внешний контур.

7. При необходимости вручную исправить rough-контур.

8. Задать диапазон диаметров отверстий.

9. По явной команде найти rough-отверстия.

10. Исправить отверстия и их группировку.

11. По явной команде найти внутренние вырезы.

12. Исправить внутренние вырезы.

13. По явной команде создать reduced point cloud около
    подтверждённой rough-геометрии.

14. Перейти ко второму этапу работы с реальными точками.

15. При необходимости удалить ошибочные точки.

16. Задать требуемый односторонний допуск.

17. По явной команде выполнить точное восстановление геометрии
    без захода автоматического контура в область материала детали.

18. Исправить необходимые CAD-элементы.

19. При необходимости зафиксировать пользовательские элементы.

20. Повторно уточнять свободные участки относительно fixed geometry.

20a. При необходимости отдельно запустить Geometry Optimization
     и повторную проверку результата.

21. Проверить итоговый контур и отверстия.

22. Сохранить проект.

23. Экспортировать итоговую геометрию в DXF; при неприменённых
    precise-изменениях отменить экспорт или явно продолжить.

Возврат к изменению rough-stage после начала precise-stage требует
подтверждения полного сброса без Undo. После сброса второй этап
начинается новым явным Build Reduced Point Cloud.
```

## 37. Основные обязательные принципы

При дальнейшей разработке должны сохраняться следующие принципы:

1. Большое исходное облако не загружается целиком в память.
2. Исходный текстовый файл после импорта не должен постоянно перечитываться.
3. `cell` является фиксированным свойством конкретной density map.
4. Zoom не изменяет физическое разрешение density map.
5. Первый этап работает с PNG, второй — с реальными точками.
6. Rough-геометрия не считается финальной точной геометрией.
7. Повторный поиск на первом этапе заменяет результат, а не пытается интеллектуально объединять его с ручными изменениями.
8. Последующие операции первого этапа используют текущее исправленное состояние rough-геометрии.
9. Трудоёмкие операции запускаются только явно пользователем.
10. Внутри этапа изменения могут оставаться неприменёнными без автоматического тяжёлого пересчёта; изменение rough-входов после начала precise-stage требует подтверждённого полного сброса без Undo.
11. На втором этапе пользовательская фиксированная геометрия имеет приоритет над автоматическим fitting.
12. Автоматически построенная точная геометрия не должна заходить в область материала детали; допустимая погрешность направлена только в сторону сохранения дополнительного материала.
13. Если односторонний допуск невозможно соблюсти, алгоритм не должен выдавать нарушающий его результат как корректный.
14. Контуры должны оставаться непрерывными.
15. Реальные углы не должны автоматически сглаживаться.
16. Итоговая геометрия должна состоять из разумного минимального количества CAD-примитивов в пределах требуемого качества и одностороннего допуска.
17. Проект должен быть сохраняемым и пригодным для продолжения работы в другом сеансе.
18. Итоговый DXF должен сохранять геометрический смысл объектов и быть пригодным для дальнейшей CAD-работы.
