Собственные probes (worker_probes.cpp, production sources без изменений):
1. Pending move construction/assignment уничтожает заменяемый D, сохраняет
   перемещённый D; releaseToOwner повторяемо возвращает empty после передачи;
   принятый файл переживает все guards. Literal D counts {2,0,0,1}, shape 2x2.
2. Перемещённый PendingDataset при discard удаляет ровно свой файл; moved-from
   owners не удаляют его раньше времени и не удаляют source cache.
3. После возврата builder, разрушения request и всех moves callback context
   всё ещё удерживается. Windows sharing lock провоцирует настоящий отказ
   QFile.remove; callback получает CleanupFailure/Cleanup, context живёт во
   время callback и освобождается после pending destruction. Orphan сохранён
   до снятия lock и удалён только самим probe.
4. Через production controller/runner/adapter receiver.prepare создаёт foreign
   child внутри scratch и отказывает. D удалён, чужое содержимое сохранено,
   structured cleanup warning виден; probe удаляет только созданный им child.
5. Через тот же pipeline output блокируется в prepare и получает Discard.
   Nested Density CleanupFailed не стирается directory warning; orphan остаётся
   доступным. После снятия lock/cleanup следующий Build не наследует warning.
