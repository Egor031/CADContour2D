B. ЗАМЕЧАНИЯ P0–P3

B1. [P1] Допустимый повреждённый event index незаметно меняет exact counts

Файл: D:/ZherlitsynEE/CADContour2D/src/density/density_builder.cpp:524–531.
Связанные места: Group на строке 116; запись LE32 на 377–389; проверка длины
на 507–510; итоговые event/tile равенства на 572–574 и D consistency на 598–599.

Group хранит count/exists, но не fingerprint записанного event stream. При чтении
проверяются длина, local index bounds/partial shape, количество событий и EOF.
Содержимое, изменённое на другой допустимый index, не проверяется против записи.

Независимое воспроизведение в Debug и Release:
  Штатный Point Cache Writer: points [(0,0),(1,0),(2,0)], cell=1.
  Буквальный ожидаемый tile 2x1: [1,2], maximum 2 включён в последнюю ячейку.
  Baseline production Build -> обычный D Reader: [1,2], fullValidate success.
  Через существующий Reopen seam перед реальным чтением изменён один бит
  первого LE32 event: 0 -> 1. Только собственная временная spool-fixture.
  До:    000000000100000001000000
  После: 010000000100000001000000
  Получено: Build SUCCESS, counts [0,3], обычный D Reader fullValidate SUCCESS.
  scanAll=1; source/scanned/events-written/read/accumulated/tile/D totals=3.
  Source SHA-256 не изменился; discard и cleanup корректны.

Это новый дефект builder, не baseline-дефект D: D корректно защищает CRC уже
ошибочных counts, переданных ему после повреждения. Совпадение totals не доказывает
пространственное распределение. Нарушены запрошенная целостность spool и exact
source-to-cell результат. Это deterministic injection, а не утверждение о
воспроизведённом physical device fault или об аутентификации против злоумышленника.

Направление исправления: поддерживать ожидаемый per-group fingerprint точного
успешно записанного LE32 stream и сверять его при чтении до успешного завершения
группы/Build; например CRC с уже имеющейся zlib. Учесть дополнительную metadata
в общем accounting. Добавить regression для in-range bitflip и same-length
wrong-content stream. Повторный source scan и изменение Point Cache/D не требуются.

Доказательства: resources/spool_probe.cpp, resources/CMakeLists.txt,
resources/probe-debug.log, resources/probe-release.log, resources/hashes.json,
resources/resource-review.md. Exit 0 воспроизводителя означает подтверждение
дефекта, а не PASS исправности production.

B2. [P2] Windows drive/root-relative output и scratch проходят absolute guard

Файл: D:/ZherlitsynEE/CADContour2D/src/density/density_builder.cpp:303–305.

Source проверяется std::filesystem::path::is_absolute(), output и scratch —
QFileInfo::isAbsolute(). В фактической Qt 6.12 Windows второй predicate возвращает
true для «D:drive-relative», «/root-relative» и «\root-relative». Эти формы зависят
от CWD/current drive и не являются полностью квалифицированными Windows paths.

Независимое воспроизведение в Debug и Release:
  Request.outputPath = "D:relative-result.density".
  Preflight progress callback меняет CWD на собственный fixture chosen-cwd.
  Production Build возвращает SUCCESS; pending.path указывает на файл внутри
  chosen-cwd. Callback изменил фактический смысл уже переданного output request.
  Отдельный Build с абсолютным output и scratchParent="D:relative-scratch"
  также возвращает SUCCESS. Проверки только внутри собственных fixture directories.

Последствие: результат/scratch оказываются в месте, выбранном текущим рабочим
каталогом, несмотря на заявленный immutable absolute-path contract. Existing target
при этом не перезаписан, но обязательная независимость от CWD нарушена.

Направление исправления: единообразно требовать полностью квалифицированные
Windows paths для source/output/scratch до файловых операций; сохранить поддержку
абсолютных drive/UNC paths. Добавить regression для drive-relative/root-relative
форм и изменения CWD из callback. Исправление форматов не требуется.

Доказательства: lifecycle/main.cpp, lifecycle/CMakeLists.txt,
lifecycle/run.log, lifecycle/run-debug.log, lifecycle/hashes.json,
lifecycle/review.md. Строки BUG accepted=1 подтверждают дефект, несмотря на
успешный exit characterization harness.

D. РЕСУРСЫ И LIFECYCLE

Общее resource accounting в исследованных путях связно. Fixed event allocation
ограничен capacity; occupied std::map заряжает реальные allocation requests,
включая sentinel/nodes, до allocation. Metadata — sub-ceiling working RAM.
Reader/events уничтожаются до accumulation; counts/tile/wire — до finish.
Одновременно живущие D buffer+codec+sort reservations включены в фазовую сумму,
а не получают каждый полный общий working ceiling. Sort/codec/readback и source
reader учитываются своими reservations; base/path bookkeeping — инженерный reserve.

Payload 4*N проверяется с overflow/qint64 и удерживается в disk policy до конца D,
даже после удаления spools. D получает остаток scratch/combined. Это безопасная
консервативная reservation bound, а не sampled peak или повторное использование
освобождённых bytes. Files включают retained source, actual spools и четыре D files;
5 handles покрывают accumulation со spool или finish с readback. Shared work bridge
контролирует CacheReader/D checkpoints; mapping имеет отдельный явный ceiling.
Zero semantics/checked arithmetic и совместные ceilings подтверждены тестами/probes.

Accounting описывает owned allocation requests/reservations и logical file lengths.
Оно не является process/OS hard cap, размером физического размещения файлов,
гарантией свободного диска или подтверждённым эксплуатационным пределом. Initial
ceilings — изменяемый caller профиль. Дополнительных конкретных resource defects,
кроме B1 целостности event bytes и B2 path semantics, не найдено.

Snapshot копируется до callbacks, retained const binding живёт до завершения
Engine, borrowed batches не сохраняются. Проверяются CacheId/count/binary64 bounds;
пустой source отклоняется, непустые degenerate axes работают. Никакой зависимости
от mutable ProjectState/GUI нет. Зависимость output/scratch от CWD остаётся B2.

Успешный C1 вызывает ровно один CacheReader::scanAll, без spatial queries/re-scan.
Каждая запись передаётся принятому Mapping.locate, без собственного ceil/floor/
clamp/epsilon/coordinate rounding. Count arithmetic checked uint64 до D Writer.
Tile keys pair-based, partial stride корректен, tile не подаётся повторно.
Равенства totals/EOF проверяются, но не закрывают содержательную integrity дыру B1.

D retained context API сохраняет прежние вызовы через default optional retention;
wire format не изменён. Diagnostics содержит callback/shared user context/optional
cleanup error; ссылок на Engine/request/stack и ownership cycle не найдено.
Pending move/destruction порядок корректен и проверен в обеих конфигурациях.
Primary cache/sink/density failures не подменяются обёрткой или cleanup diagnostic.
Cleanup failure после finish запрещает builder success. Cancellation после finish
удаляет pending; явно releaseToOwner переданный файл сохраняется. Existing target,
source и прежний sentinel dataset сохранены. Удаляются только собственные ресурсы;
диагностируемый cleanup orphan при locked file не объявляется success cleanup.
